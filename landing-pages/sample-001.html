Embedded Dashboard

From install to request inspection.

Mount the middleware in your existing Node.js application and open its dashboard at /_devtools.

01

Install

Add the lightweight developer instrumentation package to your project.

$ npm install server-devtools
02

Initialize & Preload

Create and start your own initialization file, then preload it before your application starts. Choose any filename and location.

Initialize once · preload before app imports
03

Import & Inspect

Import that same instance in your application, mount its middleware, and open /_devtools to inspect requests.

http://localhost:3000/_devtools
Request Inspection

Everything that happened during a request.

http

HTTP Requests

Inspect method, route and path parameters, query parameters, request headers and body, and response headers, body, and status.

account_tree

Execution

Follow middleware, handlers, database operations, and outbound calls within a request.

database

Database Operations

Inspect captured MongoDB operations and their timing.

cloud_sync

External APIs

Inspect outbound native Node.js HTTP/HTTPS and fetch/Undici calls, including request and response headers and bodies.

bug_report

Errors & Exceptions

Inspect request-associated errors with available message, type, and stack information.

timer

Timing

See duration across the request execution tree and compare operation timings.

In-Process Runtime

Runs inside your application.

ServerDevTools runs inside your Node.js application, instruments backend activity, persists inspection history to SQLite, and serves its dashboard from your existing HTTP server without requiring a separate ServerDevTools web server.

check_circle Embedded in your existing Node.js application
check_circle Dashboard served from /_devtools
check_circle SQLite-backed inspection history 
// server-devtools.ts (example filename; choose your own)
import ServerDevTools from "server-devtools";

export const devtools = new ServerDevTools({
  auth: {
    username: process.env.SERVER_DEVTOOLS_USERNAME!,
    password: process.env.SERVER_DEVTOOLS_PASSWORD!,
  },
  // Optional encryption at rest.
  encryption: {
    key: process.env.SERVER_DEVTOOLS_ENCRYPTION_KEY!,
    fields: ["authorization", "password", "token"],
  },
});

await devtools.start();

// src/main.ts
import { createServer } from "node:http";
import { devtools } from "../server-devtools";

const server = createServer((req, res) => {
  devtools.middleware(req, res, () => {
    res.statusCode = 404;
    res.end("Not found");
  });
});
server.listen(3000);

# Development
npx tsx --import ./server-devtools.ts src/main.ts

# Production
node --import ./dist/server-devtools.js ./dist/main.js

// src/main.ts
import "reflect-metadata";
import { NestFactory } from "@nestjs/core";
import { AppModule } from "./app.module";
import { devtools } from "../server-devtools";
import ServerDevToolsNestInterceptor from "server-devtools/dist/src/integrations/nestjs/server-devtools-nest.interceptor.js";

async function bootstrap() {
  const app = await NestFactory.create(AppModule);
  app.use((req, res, next) => devtools.middleware(req, res, next));
  app.useGlobalInterceptors(new ServerDevToolsNestInterceptor());
  await app.listen(3000);
}

bootstrap();

Same HTTP server · /_devtools Sensitive captured fields can be encrypted before local storage. By default: password, accessToken, refreshToken, authorization, cookie. A custom fields list replaces these defaults.
Workflow Shift

Stop digging through terminal logs.

When an endpoint fails or slows down, see the HTTP request, full execution path, database queries, external network calls, and errors correlated together.

Without ServerDevTools close
  • ✕ Add console.log("here 1")
  • ✕ Grep through messy terminal stdout
  • ✕ Restart node server process
  • ✕ Manually re-trigger request from curl / Postman
  • ✕ Guess which external dependency stalled
Request details and execution context spread across logs
With ServerDevTools check
  • ✓ Open http://localhost:3000/_devtools
  • ✓ Click the failing or slow request in table
  • ✓ Inspect database and outbound HTTP activity in context
  • ✓ Review request timing and associated errors
